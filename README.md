# go_to_market

시장에 가면~ **AI 대결 버전**

주제를 정하고 AI 와 번갈아 단어를 쌓는 기억력 게임입니다.
[reference/market.html](reference/market.html) 의 1인용 버전을 바탕으로,
단어의 주제 적합성을 **심판 AI** 가 판정하도록 바꿨습니다.

기본값은 **로컬 모델(Ollama)** 입니다. 인터넷도 API 키도 없이, 비용도 없이 돌아갑니다.
내가 낸 단어의 판정은 2~3초, AI 차례는 평균 4~5초입니다.

---

## 실행

### 1. Ollama 설치와 모델 받기

```bash
winget install --id Ollama.Ollama --exact
```

```bash
ollama pull exaone3.5:7.8b
```

`ollama serve` 는 설치 시 백그라운드 서비스로 함께 등록됩니다.
`curl http://localhost:11434/api/tags` 가 응답하면 준비된 것입니다.

### 2. 게임 서버

```bash
npm install
```

```bash
cp .env.example .env
```

국어사전 표제어 목록을 받습니다(4MB, 한 번만). 이걸 건너뛰면 AI 가 지어낸 말을 걸러내지 못합니다.

```bash
npm run setup:dict
```

```bash
npm start
```

http://localhost:3000 을 열면 됩니다.
서버가 켜질 때 모델을 미리 VRAM 에 올려두므로, 첫 턴부터 바로 빠릅니다.

모델 없이 화면 흐름만 보고 싶다면:

```bash
npm run mock
```

### 3. 모델 비교

어떤 로컬 모델을 쓸지는 재보고 정하는 게 좋습니다.

```bash
node bench/run.js qwen3:4b exaone3.5:7.8b
```

판정 정확도(SEEN/HELD 로 나눠서), 애매한 단어의 재질문 일관성,
생성 품질, 응답 시간을 표로 뽑아줍니다.

실제 게임 루프를 그대로 돌려 보려면 (채택되는 단어와 턴당 대기 시간을 봅니다):

```bash
node bench/game-sim.js 시장 15
```

## 게임 규칙

### 주제는 "장소" 여야 합니다

`<주제>에 가면 ~도 있고` 라는 말놀이라, 주제가 장소가 아니면 판정 기준 자체가 흔들립니다.
실제로 주제를 `게임` 으로 두었더니 심판이 지어낸 이름(`카르네시아`)까지 통과시켰습니다 —
그 단어가 실재하는 게임인지 모델이 판단하지 못하기 때문입니다.

그래서 주제를 **안에 무언가가 들어 있는 공간**으로 묶었습니다.
검사는 두 겹이고, [`server/topic.js`](server/topic.js) 와 `validateTopic()` 이 나눠 맡습니다.

| 검사 | 누가 | 걸리는 예 | 시간 |
|---|---|---|---|
| 국어사전에 있는 낱말인가 (조어 차단) | 코드 | `시장과일`, `냉장고채소`, `할머니김치` | 0ms |
| 안에 물건이 들어 있는 공간인가 | 모델 | `여름`(때), `게임`(개념), `아이유`(사람) | 2~3초 |

`시장`, `목욕탕`, `냉장고`, `서랍`, `할머니 댁`, `정육점` 처럼 물건이 담긴 곳이면 통과합니다.
AI 의 주제 추천도 같은 관문을 통과한 것만 내놓습니다.

1. 주제를 직접 입력하거나 `🎲 AI에게 추천받기` 로 고릅니다.
2. **내 차례** — 지금까지 나온 단어를 **순서대로 다시 입력**한 뒤, 새 단어를 하나 추가합니다.
3. 새 단어는 심판 AI 에게 보내집니다. 주제에 맞지 않으면 그 자리에서 패배입니다.
4. **AI 차례** — AI 가 새 단어를 하나 냅니다. 이 단어도 외워야 합니다.
5. 암송을 틀리거나, 제한 시간을 넘기거나, 심판에게 탈락하면 게임 오버.
6. **AI 가 더 이상 주제에 맞는 새 단어를 못 내면 내가 승리**합니다.

중복 단어는 패배가 아니라 경고입니다. 다시 입력하면 됩니다.

### 이기는 것보다 기록이 중요합니다

목적이 기억력 훈련이라 한 판의 승패보다 **어디까지 갔는지**를 앞세웁니다.
끝난 화면은 "게임 오버" 가 아니라 이렇게 나옵니다.

| 상황 | 화면 |
|---|---|
| 보통 | 🧠 여기까지 왔어요 |
| 이전 최고를 넘음 | 🎉 최고 기록! |
| AI 가 주제를 바닥냄 | 🏆 AI 가 손을 들었어요 |

그리고 다음 판에 무엇을 노리면 되는지 한 줄로 알려줍니다.

```
보통 5~7번째에서 놓쳐요. 이번엔 그보다 멀리 갔어요.
최근 5판이 그 전보다 평균 2.2개 늘었어요.
오늘 6판째, 오늘 최고는 11개예요.
```

기록은 [`public/stats.js`](public/stats.js) 가 브라우저 localStorage 에만 쌓습니다.
서버로 나가지 않습니다. 판이 적을 때는 추세를 말하지 않습니다 —
없는 추세를 지어내면 훈련에 방해가 됩니다.

## AI 가 하는 일

네 가지 역할이 서로 **다른 호출**로 나뉘어 있습니다.
자기가 만든 답을 자기가 채점하면 검증이 되지 않기 때문입니다.

| 역할 | 하는 일 | 코드 |
|---|---|---|
| 🧑‍⚖️ 심판 `judge` | 양쪽이 낸 단어를 공식 판정한다. 여기서 탈락하면 패배 | [`judge()`](server/agents.js) |
| 🤖 플레이어 `generate` | AI 차례에 새 단어를 하나 만든다 | [`generateWord()`](server/agents.js) |
| 🔍 검수 `inspect` | 플레이어 AI 의 단어를 채택 전에 미리 걸러낸다 | [`inspect()`](server/agents.js) |
| 🎲 진행자 `topics` | 주제를 추천한다 | [`suggestTopics()`](server/agents.js) |

심판과 검수는 **같은 판정 기준(`RUBRIC`)** 을 글자 그대로 공유합니다.
기준이 다르면 AI 만 억울하게 불리해집니다.

### AI 차례의 루프

[`server/game.js`](server/game.js) 의 `playAiTurn()` 이 이 순서로 돕니다.
**앞의 넷은 코드(0ms), 뒤의 둘만 모델**입니다.

| 단계 | 누가 | 무엇을 막나 | 실제로 잡힌 것 |
|---|---|---|---|
| 1. 주제 반복 | 코드 | 주제어를 그대로 냄 | `시장` 주제에 `시장` |
| 2. 중복 | 코드 | 이미 나온 단어 | `쪽파` 반복 |
| 3. 조어(포함) | 코드 | 이미 나온 낱말을 품은 말 | `시장길`, `도깨비시장` |
| 4. 국어사전 | 코드 | 지어낸 합성어 | `과일상자`, `함바키`, `채소자루` |
| 5. 검수 AI | 모델 | 주제 부적합 | `망치`, `도자기` |
| 6. 심판 AI | 모델 | 최종 판정 | *(같은 모델이면 자동 생략)* |

**판단할 수 있는 것은 전부 코드로 내립니다.** 모델에게 물어야 하는 건
"이 단어가 이 주제에 어울리는가" 하나뿐입니다.

#### 단어를 하나씩 받지 않고 묶음으로 받는 이유

모델에게 단어를 하나씩 "떠올려" 달라고 하면 없는 말을 지어냅니다
(`흥정소리`, `냄새꾼`, `함바키`). 여러 개를 한 번에 "나열" 하게 하고
실재어 판별을 코드가 맡으면, **같은 모델이 훨씬 나은 답을 냅니다.**
받아 둔 낱말은 주제별 풀에 쌓아 두므로 대부분의 턴에서 생성 호출이 아예 없습니다.

[`bench/gen-strategy.js`](bench/gen-strategy.js) 측정
(exaone3.5:7.8b, 주제 "시장", 쓸 만한 단어 12개를 얻는 비용):

| 전략 | 호출 | 총시간 | 얻은 단어 | 단어당 |
|---|---|---|---|---|
| 하나씩 (규칙 문장만) | 12번 | 17.9초 | 7개 | 2.6초 |
| 하나씩 + few-shot | 12번 | 17.7초 | 10개 | 1.8초 |
| **묶음 20개 + 코드 선별** | **1번** | **6.9초** | **12개** | **0.6초** |

few-shot 예시만 넣어도 7 → 10 으로 오릅니다. 규칙을 길게 적는 것보다
좋은 답이 어떻게 생겼는지 보여 주는 편이 작은 모델에는 훨씬 잘 먹힙니다.

풀을 두 번 새로 채워도 쓸 만한 낱말이 나오지 않으면
주제가 바닥난 것으로 보고 AI 가 집니다.

#### 판정은 캐시합니다

프롬프트를 아무리 다듬어도 모델은 같은 질문에 가끔 다르게 답합니다.
이 게임에서 그건 품질 문제가 아니라 **억울한 패배**로 이어집니다 —
아까는 통과시킨 단어로 이번엔 지는 일이 생깁니다.

그래서 일관성만은 모델에게 맡기지 않고 [`verdict-cache.js`](server/verdict-cache.js) 가
코드로 보장합니다. 한 번 내린 판정은 그대로 기억해 두고 다시 묻지 않습니다.
같은 주제로 재도전할 때 특히 효과가 큽니다.

```
1판  고기 통과 2344ms · 우유 통과 1574ms · 계란 통과 1816ms
2판  고기 통과    1ms · 우유 통과   11ms · 계란 통과   16ms
```

모델의 맨 판정 일관성은 83% 정도입니다(같은 단어를 두 번 물으면 6개 중 1개가 흔들립니다).
캐시가 그걸 **게임 안에서 100%** 로 만듭니다.

캐시 키에는 모델 이름이 들어갑니다. `.env` 로 모델을 바꾸면 판정 기준도 사실상
바뀐 것이므로 이전 모델의 판정을 물려받으면 안 됩니다.
메모리에만 두므로 서버를 다시 켜면 비워집니다 — 이상한 판정이 굳어 버렸을 때의 탈출구이기도 합니다.

#### 왜 6번이 자동으로 생략되는가

검수와 심판이 같은 모델·같은 기준·`temperature 0` 이면 두 호출의 답이
결정론적으로 똑같아집니다. 그때 심판은 검증이 아니라 그냥 대기 시간입니다.
`isSameEngine('inspect', 'judge')` 가 이걸 감지해 건너뜁니다.
`.env` 에서 역할별로 **다른 모델**을 지정하면 진짜 두 번째 의견이 되므로 다시 호출합니다.

#### 사람 단어는 다르게 취급합니다

| | 사람 | AI |
|---|---|---|
| 심판 판정 탈락 | **패배** | 다음 후보로 |
| 중복 | 경고 (다시 입력) | 다음 후보로 |
| 국어사전 검사 | **하지 않음** | 함 |

표제어 목록에 `방울토마토` 같은 일상어가 빠져 있어서, 사람에게 사전 검사를 걸면
멀쩡한 단어로 억울하게 지는 일이 생깁니다. AI 는 후보가 풀에 더 있으니 손해가 없습니다.

## 구조

```
server/
  index.js       Express — 정적 파일 + /api/* 라우트
  llm.js         역할 → 프로바이더 → 모델 라우팅
  ollama.js      로컬 백엔드 (JSON 스키마 강제, 온도 조절, 사전 적재)
  claude.js      Anthropic 백엔드
  agents.js      네 역할의 프롬프트와 스키마
  game.js        AI 차례의 루프, 코드로 내리는 판정 전부
  dictionary.js  국어사전 표제어 조회 (0ms)
  topic.js       주제 검사 — 조어 차단 (장소 판정은 agents.js)
  verdict-cache.js  판정 캐시 — 같은 단어에 언제나 같은 판정
  mock.js        모델 없이 돌려보기 위한 가짜 응답기
public/
  index.html     화면
  game.js        게임 상태와 화면 전환
  stats.js       훈련 기록 (localStorage, 서버로 안 나감)
scripts/
  fetch-dict.js       표제어 목록 내려받기 (npm run setup:dict)
  fetch-wiki-titles.js 위키 제목 목록 — 아래 실험 전용 (npm run setup:wiki)
bench/
  run.js           로컬 모델 비교 (판정 정확도 · 생성 품질 · 응답 시간)
  gen-strategy.js  단어 생성 전략 비교 (하나씩 / few-shot / 묶음)
  rag-vs-lookup.js 고유명사 판정 비교 (프롬프트만 / 조회표 / RAG)
  game-sim.js      실제 게임 루프를 그대로 돌려 보기
data/            받아 온 단어 목록 (git 에 올리지 않음)
```

게임 코드는 [`llm.js`](server/llm.js) 의 `askJson({ role, ... })` 만 부릅니다.
어떤 모델이 실제로 답하는지는 전부 `.env` 로 정해지고, 게임 로직은 알 필요가 없습니다.

**API 키는 서버에만 있고 브라우저로 나가지 않습니다.** 프런트는 `/api/*` 만 호출합니다.

| 엔드포인트 | 하는 일 |
|---|---|
| `GET /api/health` | 역할별 프로바이더·모델, 준비 상태, 판정 캐시 적중률 |
| `POST /api/topics` | 장소 5개 추천 |
| `POST /api/topic-check` | 사람이 쓴 주제가 쓸 만한지 검사 |
| `POST /api/judge` | 내가 낸 단어를 심판이 판정 |
| `POST /api/ai-turn` | AI 차례를 한 번 진행 |

## 설정

`.env` 에서 바꿀 수 있습니다. 자세한 목록은 [`.env.example`](.env.example) 참고.

| 변수 | 기본값 | 설명 |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | `ollama` (로컬) 또는 `anthropic` (클라우드) |
| `OLLAMA_MODEL` | `exaone3.5:7.8b` | 로컬 기본 모델 |
| `OLLAMA_KEEP_ALIVE` | `30m` | 모델을 VRAM 에 붙잡아 두는 시간 |
| `ANTHROPIC_API_KEY` | — | 클라우드를 쓸 때만 필요 |
| `REFEREE_ON_AI` | `true` | AI 단어가 검수를 통과한 뒤 심판까지 한 번 더 거칠지 |

역할별로 따로 지정할 수도 있습니다. 판정은 로컬로 빠르게, 단어 생성만 클라우드로 — 같은 조합이 가능합니다.

```
LLM_PROVIDER=ollama
LLM_PROVIDER_GENERATE=anthropic
MODEL_GENERATE=claude-opus-5
```

게임 화면 우측 상단 ⚙️ 에서 테마와 제한 시간을 바꿀 수 있습니다.
제한 시간은 **내 차례에만** 흐르고, AI 를 기다리는 동안에는 멈춥니다.

## 알아둘 점

- **온도는 프로바이더마다 다르게 씁니다.** 로컬에서는 판정을 `temperature: 0` 으로 고정해
  일관성을 잡고, 단어 생성만 `0.9` 로 올려 다양성을 줍니다.
  Anthropic 쪽은 Claude Opus 5 부터 `temperature` 를 아예 받지 않으므로(400),
  구조화 출력과 고정된 판정 기준 문장으로만 일관성을 확보합니다.
- **파인튜닝은 필요 없습니다.** 두 작업 다 베이스 instruct 모델의 제로샷 범위 안입니다.
  품질이 모자랄 때 손대는 순서는 ① 요청의 모양을 바꾸기(하나씩 → 묶음) ② few-shot 예시
  ③ 결정론적 코드로 옮기기 ④ 모델 교체 입니다. 파인튜닝은 이 넷을 다 해보고 나서입니다.
- **모델은 어휘가 실재하는지 판단하지 못합니다.** "함바키" 가 표준국어대사전에 있느냐고
  단독으로 물어도 있다고 답합니다. 그래서 그 판단만은 사전 파일로 옮겼습니다.
- **AI 는 암송을 틀리지 않습니다.** 상대가 완벽하므로 승리 조건은 사실상 "주제를 바닥내기" 하나뿐입니다.
  이기고 싶다면 `냉장고 속`, `분식집` 처럼 단어 수가 한정된 좁은 주제를 고르세요.
- **"있기는 한데 반갑지 않다" 는 탈락 사유가 아닙니다.** 한때 `과일밭`+`풀`,
  `과일밭`+`잡초`가 탈락했습니다. "정반대는 탈락" 규칙을 모델이
  "반갑지 않은 것 = 반대"로 넓혀 읽은 탓입니다. 잡초는 밭에 나는 게 당연한데도요.
  지금은 규칙에 *주제 안에 실제로 있을 수 있으면 무조건 통과* 를 못박고,
  탈락 사유를 딱 둘(이어지는 지점이 없다 / 계절·환경이 반대다)로 한정했습니다.
  `"있을 수 있지만 관련성이 부족하다"` 같은 자기모순 사유도 금지했습니다.
- **판정 기준은 관대하되, "정반대" 는 잡습니다.** 억울한 탈락이 느슨한 통과보다 나쁘다고 봤습니다.
  다만 `여름`+`눈사람` 처럼 이어지는 지점이 있어도 방향이 반대인 것은 탈락입니다.
  "무관" 과 "정반대" 를 나눈 규칙(6번)이 그 일을 합니다.
- **판정 성적은 "외운 것" 과 "이해한 것" 을 나눠 잽니다.**
  판정 예시에 넣은 쌍을 그대로 테스트하면 점수가 부풀려집니다.
  [`bench/run.js`](bench/run.js) 는 케이스를 SEEN(프롬프트 예시에 있음)과
  HELD(프롬프트에 없음)로 나눠 따로 보고합니다. 믿을 값은 HELD 쪽입니다.

  ```
  통과 · SEEN     100%  (8개 중)
  통과 · HELD      96%  (28개 중)  ✗ 과일밭/바위   ← 일반화
  탈락 · SEEN     100%  (6개 중)
  탈락 · HELD     100%  (13개 중)                 ← 일반화
  재질문 일관성    100%  (5개 중, 캐시 끔)
  ```

  `과일밭`+`바위` 하나가 남아 있습니다. 밭에 돌이 있기는 하지만
  "과일밭에 가면 바위도 있고~" 라고 하기엔 약한, 경계에 걸친 쌍입니다.
  판정 예시에 넣으면 맞힐 수 있지만 그건 테스트에 맞춰 가르치는 것이라
  그대로 두고 드러나게 뒀습니다.

  HELD 에는 `여름`+`선풍기`(통과)와 `겨울`+`선풍기`(탈락)처럼 **같은 단어가
  주제에 따라 뒤집히는 쌍**을 넣어 두었습니다. 외워서는 맞힐 수 없는 쌍입니다.
  기준은 [`server/agents.js`](server/agents.js) 의 `RUBRIC` 하나이고, 심판과 검수가 글자 그대로 공유합니다.
  더 빡빡하게 하려면 1번·5번 항목을 고치면 됩니다.
- **판정 기준에 "실재하는 낱말인가" 항목을 두지 않습니다.** 한때 있었는데, 기준 중
  가장 길고 "탈락" 이 많이 나오는 부분이라 모델이 그쪽으로 기울어
  `냉장고`+`고기`, `냉장고`+`우유` 까지 탈락시켰습니다("보관되지만 관련성이 낮다").
  실재성 판단은 [`dictionary.js`](server/dictionary.js) 가 코드로 하므로 기준에서 뺐습니다.
- **판정에도 few-shot 예시가 들어 있습니다.** 규칙 문장만으로는 이 크기의 모델이
  "보관한다" 를 관련성으로 인정하지 않습니다.
